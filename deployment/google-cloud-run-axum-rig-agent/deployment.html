1. Overview

The service started as a minimal, public Axum endpoint that streamed a Rig agent's reply token-by-token. It became a small, cost-conscious, authenticated product deployed to Cloud Run.

Browser ──HTTPS──▶ Cloud Run service "axum-streaming"
                    │
                    ├── GET  /                → chat UI (session required)
                    ├── POST /chat            → SSE stream from Rig → DeepSeek
                    ├── GET/POST /login       → argon2id check, JWT cookie
                    ├── GET/POST /change-password
                    ├── POST /logout
                    └── GET  /health          → probe target
                    │
                    ├── Secret Manager .. DEEPSEEK_API_KEY
                    │                     SESSION_SECRET
                    └── Cloud Storage ... users.json
                                          { email, argon2 hash, must_change }

Design constraints that drove the shape:

  • Stateless compute. Cloud Run instances come and go, so users and sessions must live outside the container. Sessions are self-contained signed JWTs; users live in a single GCS object.
  • Cost. Scale to zero, a hard cap of 5 instances, and an in-app idle watchdog that exits after 30 minutes without traffic.
  • Secrets never in the image. Both the DeepSeek key and the session-signing key come from Secret Manager at runtime.

2. Rust code changes

2.1 Fail fast on a missing key

Rig 0.43 accepts an empty DEEPSEEK_API_KEY and only fails with a 401 on the first request. Reject it at startup instead:

if std::env::var("DEEPSEEK_API_KEY").unwrap_or_default().trim().is_empty() {
    return Err(std::io::Error::new(
        std::io::ErrorKind::NotFound,
        "DEEPSEEK_API_KEY is not set or empty.",
    ).into());
}

2.4 Idle self-shutdown (30 min)

A middleware records the last non-health request in an AtomicU64; a background task signals a watch channel; axum::serve shuts down gracefully. Health probes are excluded so they cannot keep the process alive.

let (shutdown_tx, mut shutdown_rx) = tokio::sync::watch::channel(false);
tokio::spawn(async move {
    let mut ticker = tokio::time::interval(Duration::from_secs(tick));
    loop {
        ticker.tick().await;
        let idle = now_secs() - last_activity.load(Ordering::Relaxed);
        if idle >= idle_timeout { let _ = shutdown_tx.send(true); return; }
    }
});
axum::serve(listener, app)
    .with_graceful_shutdown(async move { let _ = shutdown_rx.changed().await; })
    .await?;

2.5 Authentication module (src/auth.rs)

  • Hashing — argon2id via the argon2 crate.
  • Sessions — HS256 JWT from jsonwebtoken, carried in a session cookie (HttpOnly; Secure; SameSite=Lax). Claims: sub, exp, must_change.
  • Store — one JSON document. With USERS_BUCKET set it is a GCS object read/written through the GCS JSON API using a token from the metadata server; otherwise a local file.
  • Seed — on first run with no store, seed AUTH_EMAILS with random temporary passwords and must_change_password = true, and print them once.
  • Concurrency — the seed upload uses ifGenerationMatch=0 so racing instances cannot both create it.
// password hashing
let salt = SaltString::generate(&mut OsRng);
let hash = Argon2::default()
    .hash_password(password.as_bytes(), &salt)?.to_string();

// session
encode(&Header::default(), &claims, &EncodingKey::from_secret(&secret))?;

// GCS read (Cloud Run metadata token)
GET https://storage.googleapis.com/storage/v1/b/{bucket}/o/users.json?alt=media
Authorization: Bearer <metadata-server-token>

3. Build & run locally

cargo build --release

export SESSION_SECRET="$(openssl rand -base64 32)"
export COOKIE_SECURE=false        # plain HTTP locally
export USERS_FILE=./users.json    # file-backed store
PORT=3977 cargo run --release

First run prints two temporary passwords (one per seeded email) and forces a password change at login. The Secure flag must be off locally or the browser drops the cookie.

4. Container image

Multi-stage build: rust:1.95-slim compiles the binary, debian:trixie-slim is the runtime. Dependencies are built in their own layer for caching; the final image runs as UID 10001.

docker build -t axum-streaming .

docker run --rm -p 3977:3977 \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -e SESSION_SECRET="$SESSION_SECRET" \
  -e COOKIE_SECURE=false \
  axum-streaming
include_str! bakes the HTML pages into the binary, so static/ only needs to exist at build time, not at runtime.

5. GCP one-time setup

Everything below is run once per project. Substitute your project id.

PROJECT=axum-streaming-6187
REGION=us-central1

gcloud config set project "$PROJECT"

gcloud services enable \
  run.googleapis.com artifactregistry.googleapis.com \
  cloudbuild.googleapis.com secretmanager.googleapis.com

Registry

gcloud artifacts repositories create axum \
  --repository-format=docker --location="$REGION"

Secrets

printf '%s' "$DEEPSEEK_API_KEY" | gcloud secrets create deepseek-api-key --data-file=-
openssl rand -base64 32 | tr -d '\n' | gcloud secrets create session-secret --data-file=-

User store bucket + IAM

PROJECT_NUMBER=$(gcloud projects describe "$PROJECT" --format='value(projectNumber)')
BUCKET="axum-streaming-users-${PROJECT}"
gcloud storage buckets create "gs://${BUCKET}" --location="$REGION"
gcloud storage buckets add-iam-policy-binding "gs://${BUCKET}" \
  --member="serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com" \
  --role="roles/storage.objectAdmin"

Cloud Build permissions

CB_SA="${PROJECT_NUMBER}@cloudbuild.gserviceaccount.com"
for ROLE in roles/run.admin roles/artifactregistry.writer \
            roles/iam.serviceAccountUser roles/secretmanager.secretAccessor; do
  gcloud projects add-iam-policy-binding "$PROJECT" \
    --member="serviceAccount:${CB_SA}" --role="$ROLE" --quiet
done

Leave the bucket empty; the service seeds it on first start and prints the temporary passwords to its logs.

6. Deploy with Cloud Build

gcloud builds submit --config cloudbuild.yaml

cloudbuild.yaml runs four steps:

  1. ensure-repo — create the Artifact Registry repo if absent.
  2. build — docker build, tagged :$BUILD_ID and :latest.
  3. push — push all tags to Artifact Registry.
  4. deploy — gcloud run deploy with secrets, env vars, probes, and scaling.
# key deploy flags
--set-secrets=DEEPSEEK_API_KEY=deepseek-api-key:latest,SESSION_SECRET=session-secret:latest
--set-env-vars=IDLE_TIMEOUT_SECS=1800,USERS_BUCKET=axum-streaming-users-$PROJECT_ID,USERS_OBJECT=users.json,COOKIE_SECURE=true
--port=8080 --timeout=3600 --concurrency=20 --min-instances=0 --max-instances=5
--startup-probe=httpGet.path=/health,httpGet.port=8080
--liveness-probe=httpGet.path=/health,httpGet.port=8080
Tags use $BUILD_ID, not $SHORT_SHA. $SHORT_SHA is only populated for Git-triggered builds; on a manual gcloud builds submit it is empty and produces the invalid tag …/image:.

7. Verify

URL=$(gcloud run services describe axum-streaming \
  --region=us-central1 --format='value(status.url)')

curl -s $URL/health                                  # 200 ok
curl -s -o /dev/null -w '%{http_code}\n' $URL/        # 303 -> /login
curl -s -o /dev/null -w '%{http_code}\n' $URL/login   # 200

Sign in with a temporary password; the first response redirects to /change-password, and /chat returns 403 until the password is changed and 401 without a session.

Retrieve the seeded temporary passwords from the logs:

gcloud logging read \
  'resource.type="cloud_run_revision" AND resource.labels.service_name="axum-streaming" AND textPayload:"Temporary passwords"' \
  --limit=1 --format='value(textPayload)' --freshness=1d

8. Authentication model

ConcernChoice
Password storageargon2id PHC strings inside the JSON document.
SessionHS256 JWT, exp checked on decode; no server-side session table.
Cookiesession, HttpOnly, SameSite=Lax, Secure (toggle with COOKIE_SECURE).
AuthorizationOnly emails in AUTH_EMAILS; seeded accounts are gated behind a password change.
Persistenceusers.json in GCS, written on password change.
CSRFMitigated by SameSite=Lax. Login is not rate-limited.
The service is deployed with --allow-unauthenticated so the login page is reachable — the app itself enforces the account list. Every request still spends your DeepSeek credits, so cap instances and consider Cloud Armor.

9. Cost control & scripts

  • --min-instances=0 — scale to zero; idle time is free.
  • IDLE_TIMEOUT_SECS=1800 — the app exits after 30 min without a request (probes excluded).
  • --max-instances=5 — bounds burst spend.
scripts/stop.sh    # delete the Cloud Run service (no paused state exists)
scripts/start.sh   # redeploy the existing :latest image

Both accept SERVICE= REGION= REPO= SECRET= SESSION_SECRET= PROJECT= overrides.
